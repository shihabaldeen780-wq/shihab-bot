# بوت شهاب — إدارة مجموعات عربية واقعية

هذا المشروع يعيد بناء فكرة البوت الموجودة في الملف المرفق بصورة أكثر أماناً واستقراراً. الواجهة عربية، بينما أسماء أوامر تيليجرام الرسمية بالإنجليزية لتفادي مشكلة الأوامر العربية التي ظهرت في النسخة السابقة. كما أن إعدادات كل مجموعة مستقلة، ولا يُنفَّذ أي إجراء إداري قبل التحقق من صلاحية المشرف.

> **تنبيه أمني مهم:** التوكن الذي ظهر في الملف المرفق أصبح مكشوفاً. يجب إلغاؤه فوراً من `@BotFather` وإنشاء توكن جديد، ثم وضعه في `.env`. لا تضع التوكن داخل `bot.py` أو ترسله في محادثة عامة.

## ما تم تحسينه

يضم الإصدار الجديد قائمة تفاعلية عربية، حماية من الروابط والتكرار، قفل وفتح الصور والفيديو والصوت والملفات والملصقات والمتحركات والتوجيه، نظام تحذيرات مع إجراء تلقائي بعد ثلاث مخالفات، كتم مؤقت يُرفع تلقائياً، سجن، ترحيب قابل للتخصيص، قوانين، ردود مخصصة، أوامر طبيعية مثل «قفل الروابط» و«تفعيل الترحيب»، معلومات المستخدم، لوحة مالك، بث، سجل أحداث، وبحث يوتيوب اختياري.

الخدمة لا تدّعي معرفة تاريخ إنشاء حساب تيليجرام الحقيقي؛ تيليجرام لا يرسل هذه المعلومة إلى البوت. لذلك يعرض `/age` توضيحاً صريحاً، ويعطي `/id` المعلومات المتاحة فعلياً.

## التشغيل على Windows بضغطة واحدة

انسخ مجلد المشروع إلى جهاز Windows، ثم افتح ملف `start_windows.bat` بالنقر المزدوج. سيقوم الملف بإنشاء البيئة الافتراضية، تثبيت المتطلبات، إنشاء `.env` عند الحاجة، وفتح البوت مع إعادة التشغيل التلقائي بعد أخطاء الشبكة. في أول تشغيل، املأ `BOT_TOKEN` و`OWNER_ID` داخل `.env` ثم شغّل الملف مرة أخرى.

يجب تثبيت Python 3 أولاً من [python.org](https://www.python.org/downloads/windows/) مع تفعيل خيار **Add Python to PATH** أثناء التثبيت. لا تضع ملف `.env` أو التوكن داخل GitHub.

## التثبيت على Termux أو Ubuntu

أنشئ مجلداً للمشروع ثم انسخ الملفات إليه. بعد ذلك نفّذ:

```bash
python -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
cp .env.example .env
nano .env
python bot.py
```

في Termux يمكن استخدام `python` بدلاً من `python3`، وإذا لم يدعم النظام البيئات الافتراضية فاستعمل:

```bash
pip install -r requirements.txt
cp .env.example .env
nano .env
python bot.py
```

ملف `.env` يجب أن يحتوي على:

```env
BOT_TOKEN=التوكن_الجديد
OWNER_ID=رقم_معرف_المالك
DB_PATH=data/shihab.db
```

يمكن معرفة `OWNER_ID` من أمر `/id` بعد تشغيل البوت. لا تستخدم معرفاً مكتوباً داخل الكود.

## إعداد البوت داخل المجموعة

أضف البوت إلى المجموعة وارفعه مشرفاً مع صلاحية حذف الرسائل وتقييد الأعضاء وحظرهم عند الحاجة. عطّل **وضع الخصوصية** من `@BotFather` إذا كنت تريد أن يقرأ البوت الرسائل النصية العادية ويرد على الكلمات، ثم جرّب `/start` و`/settings`.

## آلية النسخة الاحترافية

تتضمن النسخة الحالية طبقات مشابهة لبوتات الحماية المعروفة: إدارة فعلية عبر Telegram Bot API، رتب مخصصة لكل مجموعة، قوائم المشرفين والمكتومين والمسجونين، سجل إجراءات، حماية عامة من مستخدمين محظورين، خطط free وVIP مع شحن وفحص من لوحة المالك، مساعدين للمطور، إحصائيات، بث، إعدادات مستقلة، وردود وأوامر مخصصة، ومركز ألعاب عربي يحفظ النقاط والانتصارات واليومية والمتصدرين والإنجازات لكل مجموعة. الرتب المخصصة للعرض والتنظيم ولا تمنح صلاحيات تيليجرام تلقائياً؛ منح صلاحية مشرف يتم فقط عبر أمر رفع مشرف وبصلاحيات محددة وبشرط أن يكون البوت قادراً على ذلك.

| `صلاحياتي`، `صلاحياته`، `معلومات المجموعة`، `الساعة`، `التاريخ` | خدمات المعلومات |

## النشر على Koyeb المجاني

النسخة تحتوي الآن على `webhook_app.py` و`Dockerfile` لتعمل على Koyeb عبر Webhook بدلاً من Polling. أنشئ خدمة Web Service من مستودع GitHub أو ارفع المشروع، ودع Koyeb يبني `Dockerfile`. اضبط المنفذ على `8000` أو اتركه يقرأ المتغير `PORT`، ثم أضف المتغيرات السرية التالية من إعدادات Koyeb:

| المتغير | القيمة |
|---|---|
| `BOT_TOKEN` | توكن البوت الجديد |
| `OWNER_ID` | `8201835611` |
| `DB_PATH` | `/app/data/shihab.db` |
| `PUBLIC_URL` | رابط خدمة Koyeb، مثل `https://اسم-الخدمة.koyeb.app` |
| `WEBHOOK_SECRET` | سر عشوائي طويل لا تشاركه |
| `PORT` | `8000` |

بعد ظهور رابط الخدمة، ضع الرابط نفسه في `PUBLIC_URL` ثم أعد النشر. اختبر `https://اسم-الخدمة.koyeb.app/health`؛ يجب أن يعيد `{"status":"ok"}`. عند بدء الخدمة تسجّل نفسها تلقائياً كـ Webhook في Telegram، وعند إيقافها تزيل التسجيل. لا تضع `BOT_TOKEN` أو `WEBHOOK_SECRET` داخل GitHub أو في ملف عام.

Koyeb Free مناسب للتجربة، لكنه محدود بموارد منخفضة، ولا يوفر Worker أو Volume دائم، وقد يدخل في Scale-to-zero بعد مدة من عدم وجود حركة. لذلك لا أضمن له تشغيل حماية 24/7 أو حفظ SQLite بشكل دائم؛ للاستخدام الجاد استخدم قاعدة بيانات خارجية أو استضافة دائمة.

## خيارات التشغيل المستمر

| طريقة التشغيل | المزايا | المقابل |
|---|---|---|
| الهاتف أو الكمبيوتر الشخصي | أبسط وأقل كلفة، ومناسب للتجربة أو الاستخدام الشخصي | يجب أن يبقى الجهاز متصلاً بالإنترنت، وقد يوقف النظام التطبيق في الخلفية |
| استضافة دائمة | يعمل 24/7 ولا يعتمد على بقاء الهاتف مفتوحاً، ويمكن تشغيله كخدمة يعاد تشغيلها تلقائياً | يحتاج إعداد استضافة وحفظ أسرار البيئة ومراقبة السجلات |

ابدأ بالطريقة الأولى للاختبار. إذا كانت المجموعة تعتمد على البوت طوال الوقت، انقل نفس المجلد إلى استضافة دائمة وشغّل `python bot.py` عبر مدير خدمات مثل systemd أو supervisor. لا تستخدم `nohup` وحده في الإنتاج لأنه لا يوفر إدارة صحيحة للأخطاء أو إعادة التشغيل.

## ملاحظات مهمة

ميزة تنزيل يوتيوب اختيارية وقد تحتاج موارد ومساحة مؤقتة؛ الكود يرفض الملفات الكبيرة تقريباً، وينظف الملفات بعد الإرسال. لا تفعّلها في مجموعة عامة إلا إذا كنت تقبل استهلاك الإنترنت والمساحة.

قاعدة البيانات SQLite موجودة في `data/shihab.db`. انسخ هذا الملف دورياً عند تشغيل البوت، ولا تنسخ `.env` إلى مستودع عام. أضف `data/` و`.env` إلى `.gitignore` إذا ستستخدم Git.
